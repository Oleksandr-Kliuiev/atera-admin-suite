# Send the requested report once

Routes were checked against official documentation on **2026-09-28**; verify current report capabilities and permissions in the UI.

1. Resolve actual recipient addresses from explicit user instruction or a unique verified account/contact record. “Selected customer” defines report scope, not automatically its recipient. “Me” needs a verified address. Ask once for missing/ambiguous addresses while preparing the report; never guess from names or domains.
2. For immediate delivery, prefer an already available native one-time send **only if the live UI provides it for this report**. Otherwise export and use the existing authorized webmail tab in **Chrome**. Follow that mail tool's supported file/download/attachment workflow. Do not claim the attachment is attached when the browser tool cannot access it; keep the verified report and report the exact capability blocker.
3. Before sending, verify sender/account, To/CC/BCC, exact report and attachment, filename/type, scope, count, dates, and absence of unrelated client data. Use a concise subject naming the scope and criterion. A specified send request is sufficient authorization; no duplicate permission checkpoint. If the export is incomplete or inconsistent, resolve the discrepancy first or clearly present the limitation for the user's decision.
4. Commit once. Verify a sent record or native success/history tied to the intended recipient/report. Distinguish submission accepted from recipient delivery. If outcome is uncertain, inspect the draft/Sent/history and **do not retry** unless evidence proves no submission occurred. Report generated/exported when sending was not completed.

### Scheduling is a different task

Operational scheduling is documented at **Reports → report clock icon → parameters → Schedule**, selecting an existing enabled Contact/User or Technician and weekly/monthly timing. It sends a summary with a report link; it is not evidence of an immediate attachment send. Do not create a recurring schedule, a new contact, or modify an existing schedule for a one-time “email this report” request.

Source: [Schedule an Operational report](https://support.atera.com/hc/en-us/articles/115012156008-Schedule-an-Operational-report).

Advanced reports have a separately documented dashboard **Send Now** delivery option with permission/plan dependencies. Use it only when that is the current verified report/UI and it preserves the exact requested detail; do not navigate through analytics as a universal workaround.

Source: [Schedule advanced reports](https://support.atera.com/hc/en-us/articles/6461075581468-Schedule-advanced-reports).
