# Other OS and cross-platform inventory

Use **Reports → Analytical reports / Advanced Reports → Presets → OS Overview → OS Distribution** for macOS, Linux and OS families absent from Microsoft licensing. Apply the entrypoint's common scope. On **2026-09-28**, Chrome verified the preset, global distribution and Linux count drilldown with device/customer/OS/version rows. Do not substitute a software package search for OS evidence.

1. Reuse or open the preset via its current link. Inspect the embedded report. If its frame remains blank, refresh once or use the visible Reports navigation; a blank/unavailable report is a blocker, not zero devices. Do not buy features or create dashboards to bypass permission/plan limits.
2. Check **Retired Agents** and other active filters. The observed preset initially had only Retired Agents, not Customer: it does **not** inherit a customer from the previous page. For global scope include all requested organizations accessible to this account; for named scope establish that customer in the detailed rows.
3. In **OS Distribution**, match the displayed OS product/family and optional edition/version/build. Include every matching build/edition row. “Linux” may span distributions; “Ubuntu” narrows the product. For a release such as Ubuntu 22.04, check **OS version** in every relevant Ubuntu drilldown; Linux kernel **OS build** is not the distribution release and OS number may be empty. Do not use **Windows 11 Readiness** as a complete OS inventory.
4. Click each matching **Number of Agents** count to open an **OS Distribution** detail dialog. It exposes agent name/link (stable device ID), customer/link, folder, OS environment/build/version/number and **Download**. **DEVICES (n Filters)** expands a read-only description of the drill criteria; it is not a customer picker. For a small complete detail set, retain matching customer rows directly; for a larger set use a complete detail download and filter locally. Use a customer filter only if the current UI actually provides one. Never send unrelated customers from a global drilldown.
5. Reconcile unique device identities with all relevant counts; cover pagination and any row/export limits. Global counts alone cannot prove customer-specific presence or absence. If detail scope or completeness cannot be established, state that limit rather than claiming a complete list or zero. Report inventory freshness separately from dashboard generation time.
6. For an authorized conditional email, use [delivery](report-delivery.md) after qualifying records are established. Include customer, device and OS/version; a short complete list can be in the body. Verified complete zero means no email.

Source: [OS Overview and drilldown fields](https://support.atera.com/hc/en-us/articles/17885207693596-Analytical-reports-OS-overview).
