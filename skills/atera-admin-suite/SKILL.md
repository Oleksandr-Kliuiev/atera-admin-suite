# Atera Admin Suite

Select one owner and execute; no skill name is required from the user. Read its entrypoint and only the requested reference/section. It loads the shared Chrome contract once. Organization/device lifecycle owners coordinate their cross-domain workflows; add a specialist only when its critical action or detailed procedure is needed.

| Request | Owner |
|---|---|
| Account identity, timezone, subscription, global defaults | [Account](../atera-account-admin/SKILL.md) |
| Technician invitations, groups, roles/scope, SSO/MFA | [Access](../atera-access-admin/SKILL.md) |
| Customers/Sites, contacts/users, folders, onboarding, transfers, offboarding | [Organization lifecycle](../atera-organization-lifecycle/SKILL.md) |
| Agents, installation, device relations/moves, retirement/deletion | [Device lifecycle](../atera-device-lifecycle/SKILL.md) |
| Thresholds, alerts, notifications, automatic tickets, auto-healing | [Monitoring](../atera-monitoring-alerts/SKILL.md) |
| Patches, automation, Configuration Policies, schedules/reboots | [Patch/policy](../atera-patch-policy-admin/SKILL.md) |
| Software bundles, installation/update/removal, App Center | [Deployment](../atera-software-deployment/SKILL.md) |
| Script library, review, runs, schedules, remediation | [Scripts](../atera-script-remediation/SKILL.md) |
| Remote sessions, terminal, processes/services/registry, live support | [Remote support](../atera-remote-support/SKILL.md) |
| Tickets, queues, SLA, forms/templates, assignment and rules | [Service desk](../atera-service-desk/SKILL.md) |
| Contracts, work logs, products/expenses, rates, invoices | [PSA/billing](../atera-psa-billing/SKILL.md) |
| Device/software lists, reports/export/email, Recent Processes, audit | [Reporting](../atera-reporting-audit/SKILL.md) |
| API keys, integrations, API reads/writes, import/export, webhooks | [Integrations](../atera-integrations-api/SKILL.md) |
| Reusable account profiles, discovery/comparison/validation | [Operations catalog](../atera-operations-catalog/SKILL.md) |

Inventory requests belong to Reporting; they do not authorize deployment or remediation.
“Does this customer / anyone still run [OS or program]?” routes to Reporting in Reports, even without the word “report.” Classify OS versus application and named-customer versus all-customer scope; do not inherit a previous customer's filter for “anyone.”
