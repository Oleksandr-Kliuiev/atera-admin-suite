# Organization change

Use for renaming, folder reorganization, contact/user updates, SLA or contract changes, profile changes, and device moves within an existing Customer/Site.

1. Verify account mode, organization ID, effective date, and requested destination objects.
2. Capture current contacts/users, folders, devices, tickets, contracts, SLA, threshold profile, configuration policy, automation profiles, and overrides.
3. Resolve destination profiles and folders by stable ID and inspect inherited effects.
4. Apply only requested changes. Do not copy all settings from a similarly named organization.
5. For moves, verify device/user relations, open tickets, alerts, policy supersession, queued actions, and billing attribution.
6. Reopen each changed surface and report downstream recalculation or propagation.

If a change alters active contract billing, broad automation, endpoint reboots, or open-ticket SLA deadlines, use the corresponding specialist checkpoint before committing.
